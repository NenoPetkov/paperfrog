# Official API verification

Reviewed 2026-09-30. This is documentation verification, not credentialed acceptance testing.

- [Binance USD-M general information](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/general-info): demo REST `https://demo-fapi.binance.com`, demo WebSocket `wss://demo-fstream.binance.com`; signed requests include timestamp, recvWindow and HMAC-SHA256. HTTP 503 may leave execution unknown. The adapter never retries a mutation automatically.
- [Binance trade REST reference](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade): normal IOC limit orders use `/fapi/v1/order`; conditional protection uses `/fapi/v1/algoOrder`, `algoType=CONDITIONAL`, `STOP_MARKET`, `triggerPrice`, `MARK_PRICE`, and `closePosition=true`. Do not combine closePosition with quantity or reduceOnly. Query/cancel ordinary and algo orders separately.
- [WebSocket routing](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/Connect) and [migration notice](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/Important-WebSocket-Change-Notice): current streams require `/public`, `/market`, or `/private` routing. Unrouted connections do not carry market/private traffic. Connections are proactively rotated before 24 hours. Demo routing still requires credentialed acceptance.
- [User stream lifecycle](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/user-data-streams): POST/PUT `/fapi/v1/listenKey`; renew at 25 minutes, before the documented 60-minute expiry. A disconnect blocks entry until reconciliation.
- [Account reference](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/account): v3 account query, position mode, multi-asset mode, symbol configuration and maintenance-margin brackets. Credential identity is bound by a non-reversible key fingerprint; this implementation does not claim that the v3 response proves a Binance UID or withdrawal permission.
- [Market data reference](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data): klines, premium index, funding history, book ticker, OI and recent OI statistics. Detailed historical coverage is limited; no old OI or order book is invented. [Spot market reference](https://developers.binance.com/en/docs/catalog/core-trading-spot-trading/api/rest-api/market) verifies matching spot REST observations.
- [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [web search](https://developers.openai.com/api/docs/guides/tools-web-search), and [model catalog](https://developers.openai.com/api/docs/models): official SDK `AsyncOpenAI.responses.parse`, Pydantic `text_format`, `web_search`, configurable `gpt-6-luna` / `gpt-6.1-sol`. Account-specific model access is not proven by a documentation listing; errors fail clearly without substitution.
- [Telegram Bot API](https://core.telegram.org/bots/api): asynchronous `getUpdates`, persisted offset, positive long-poll timeout, and `sendMessage`. Forward origin and edited update handling are enforced. [Bot creation](https://core.telegram.org/bots/tutorial) uses BotFather.
- [XGBoost API](https://xgboost.readthedocs.io/en/stable/python/python_api.html) and [scikit-learn calibration](https://scikit-learn.org/stable/modules/calibration.html): constructor early stopping, classifier/regressor objectives, chronological independent calibration. Installed pinned versions were exercised by a real offline training test.

REST behavior is mocked in offline integration tests. The testnet smoke test is read-only, opt-in, and skipped without explicit authorization/credentials. Full order, conditional-stop, user-stream, and restart behavior must be accepted on the actual exchange before the live implementation review gate can pass.
